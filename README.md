# dsh-render-document

Плагин DeepSeek Harness, который добавляет инструмент **`render_document`**: рендерит
страницы Office-документов и PDF в PNG, чтобы агент мог проверить вёрстку — **без
эскалации песочницы и без запросов подтверждения**.

English version: [README.en.md](README.en.md).

## Зачем это нужно

DSH запускает каждую команду в песочнице: ограниченный токен, Low integrity, запись
только внутри рабочей папки сессии и приватного временного каталога. Из этого следуют две
проблемы, из-за которых проверка вёрстки превращалась в бесконечные подтверждения:

1. **Встроенный LibreOffice Kit CLI под песочницей всегда падает** с `spawn EPERM`: он
   стартует свой движок через piped stdio, а песочница запрещает такие запуски. Дальше
   агент делает единственное, что разрешено документацией — эскалирует права до
   `danger-full-access`, и пользователь получает запрос подтверждения на каждый рендер.
   В журналах сессий одного пользователя это **47 запросов из 72** всех подтверждений.
2. **Microsoft Word под песочницей не работает вообще**: он наследует ограниченный токен,
   не может создать рабочий файл и показывает «Приложению Word не удалось создать рабочий
   файл. Проверьте переменную среды TEMP»; COM-вызов при этом висит или падает с
   `0x800A1772`, а объект `Document` в клиент не возвращается.

Код плагина исполняется в процессе хоста DSH — **вне** этой песочницы. Поэтому инструмент
может запустить движок с обычными правами пользователя, один раз и без подтверждений.

## Установка

```sh
dsh plugin --profile <профиль> add github:<владелец>/dsh-render-document
# затем перезапустить DSH
```

Установка host-кода требует полного доступа один раз (это ограничение менеджера плагинов
DSH, а не плагина). После перезапуска инструмент `render_document` виден агенту в любой
рабочей папке.

## Использование

Инструмент вызывается агентом, но полезно знать его контракт:

| Аргумент | Тип | Описание |
|---|---|---|
| `source` | строка, обязательный | Документ внутри рабочей папки сессии: `.docx/.doc/.odt`, `.xlsx/.xls/.ods`, `.pptx/.ppt/.odp`, `.pdf` |
| `pages` | строка | Страницы с единицы: `"1"`, `"1,3-5"`. По умолчанию все |
| `dpi` | целое | 24…600, по умолчанию 144 |
| `engine` | строка | `"libreoffice"` (по умолчанию) или `"word"` |
| `outputDir` | строка | Новая папка для PNG внутри рабочей папки; по умолчанию `preview-<имя документа>` |
| `keepPdf` | логическое | Для `engine: "word"` сохранить ещё и PDF рядом со страницами |

Результат:

```json
{
  "status": "ready",
  "engine": "word",
  "rasterEngine": "pdfium",
  "pageCount": 2,
  "dpi": 144,
  "outputDir": "C:/work/preview-report",
  "manifestPath": "C:/work/preview-report/manifest.json",
  "images": [
    { "page": 1, "path": "C:/work/preview-report/page-0001.png", "width": 1191, "height": 1684 },
    { "page": 2, "path": "C:/work/preview-report/page-0002.png", "width": 1191, "height": 1684 }
  ],
  "missingFonts": []
}
```

`status: "skipped"` означает, что в этой установке нет ни одного движка: визуальную
проверку нужно прекратить, а не искать обходные пути. Именно так этот инструмент описан во
встроенных скиллах `office-docx` / `office-xlsx` / `office-pptx`.

## Движки

| | `libreoffice` (по умолчанию) | `word` |
|---|---|---|
| Что рендерит | .docx/.doc/.odt, .xlsx/.xls/.ods, .pptx/.ppt/.odp, .pdf | .docx/.doc (+ .rtf), далее PDF растеризуется тем же движком |
| Пагинация | как её считает LibreOffice | **как её считает Microsoft Word** |
| Доступность | всегда (движок в комплекте DSH) | только если установлен Microsoft Word |
| Скорость | быстрее | медленнее (старт Word + экспорт) |

Правило выбора: для обычной проверки вёрстки — `libreoffice`; для печатных форм, где важно,
где именно Word разорвёт страницу и как встанут поля, — `word`. На одном и том же
документе (форма «Справка о регистрации», 1 страница) рендеры Word и LibreOffice
расходятся на **3 % пикселей** по всей странице — то есть проверка в LibreOffice не
показывает, что напечатает Word.

## Модель безопасности

Инструмент намеренно работает вне песочницы DSH — иначе он бессмыслен. Что это значит на
практике и чем ограничено:

- **Пути.** `source` и `outputDir` разрешаются относительно рабочей папки сессии, и любой
  путь за её пределами отклоняется. Абсолютные пути вне рабочей папки запрещены так же,
  как `../`.
- **Никакого произвольного кода.** Инструмент не принимает команды, скрипты или
  параметры движка: только документ, страницы, dpi и выбор из двух движков.
- **Аргументы передаются массивом**, без оболочки: подстановка shell-метасимволов
  невозможна.
- **Существующие каталоги не перезаписываются.** Движок создаёт новый каталог в
  эксклюзивном режиме; занятое имя — ошибка, а не тихая перезапись.
- **Сети нет.** Ни движок, ни Word-хелпер не ходят в сеть.
- **Процессы под контролем.** Word запускается скрыто, документ открывается «только для
  чтения», а экземпляр Word, который плагин не создавал (открытый пользователем), никогда
  не закрывается. При отмене вызова дочерний процесс убивается.
- **Единственный дочерний процесс с полными правами** — обёртка Word
  (`lib/word-export.ps1`); её код лежит в этом репозитории целиком.

## Требования

- Node.js ≥ 22.19.0 (как в комплекте DSH).
- Движок LibreOffice Kit — входит в поставку DSH; путь ищется автоматически
  (`DSH_OFFICE_KIT`, распакованный рантайм приложения, `$DSH_HOME/dsh-runtimes`).
- Для `engine: "word"` — установленный Microsoft Word и Microsoft Visual C++
  Redistributable v14 соответствующей разрядности.

## Диагностика

```sh
node scripts/probe.mjs --word   # где найден движок и виден ли Word
```

## Разработка

```sh
node test/paths.test.mjs          # логика выбора страниц, путей, движков
node test/tool-contract.test.mjs  # контракт инструмента и тексты результата
node scripts/smoke.mjs <документ>            # сквозная проверка на LibreOffice
node scripts/smoke.mjs <документ> --engine word --keep-pdf
```

`npm test` запускает стандартный runner (`node --test`). Внутри сессии DSH runner не
работает: он спавнит дочерние процессы с пайпами, что песочница запрещает (`spawn EPERM`) —
запускайте файлы тестов напрямую, как выше. Сквозной smoke-скрипт тоже нужно запускать в
обычном терминале: движок стартует нативный процесс с piped stdio.

## Ограничения

- Выбираются целые страницы: лист Excel или диапазон таблицы этим инструментом не
  отрендерить (у движка для этого отдельные параметры `sheet`/`range`).
- Приватный протокол движка (плитки PNG) может измениться при обновлении Kit — тогда
  плагин нужно обновить.
- Пагинация `libreoffice` не равна пагинации Word; для печатных форм используйте
  `engine: "word"`.
- Word COM — однопользовательский ресурс: параллельные вызовы выстраиваются в очередь
  движком, а не плагином.
